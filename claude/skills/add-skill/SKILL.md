# 汎用スキルの追加

どのプロジェクトでも使い回せるスキルを dotfiles に追加する。

## 背景

- `~/.claude/skills` は `${HOME}/dotfiles/claude/skills` への symlink
  (`claude/link.sh` が作成)。ここに書いたスキルはそのまま dotfiles で追跡される
- **dotfiles リポジトリは公開されている**。社内情報・シークレットを含むものは置けない

## 手順

### 1. 置き場所の判断

| 置き場所 | 向いているスキル |
|---|---|
| dotfiles (`~/.claude/skills`) | 個人用・汎用・公開して問題ないもの |
| プロジェクトの `.claude/skills` | そのリポジトリ固有の手順 |
| プラグイン | チームで配布したいもの、社内文脈を含むもの |

社内情報（社内 URL、プロダクト固有の文脈、業務手順など）を含む場合は dotfiles に置かず、
プラグインまたはプロジェクトスキルを提案する。

### 2. 既存スキルの確認

`${HOME}/dotfiles/claude/skills/` を一覧し、既存スキルで対応できる場合は
新規作成せず既存スキルの更新を提案する。

### 3. スキルの設計

- **名前**: kebab-case。動詞始まりで内容が分かるもの（例: `add-skill`, `backport-claude-settings`）
- **description**: 発火条件を決める最重要項目。「使用タイミング」として、
  ユーザーが実際に言いそうなフレーズを引用形式で複数含める
- **本文**: 具体的な行動指示を書く（「〜しない」ではなく「〜する」）。
  1 スキル 1 責務。長い参考資料は SKILL.md に詰め込まず、同ディレクトリの別ファイルに分けて参照させる

### 4. ユーザーへの提案

以下を提示して承認を得る：

- スキル名と description
- 本文の内容（全文または構成）
- 置き場所（手順 1 の判断結果と理由）

**承認を得てから作成する。勝手に作らない。**

### 5. 作成

`${HOME}/dotfiles/claude/skills/<スキル名>/SKILL.md` を作成する。
symlink 経由で即座に配置されるが、新しいスキルの認識には新規セッションが必要なことを伝える。

### 6. コミット

dotfiles リポジトリでの作業として `git status` / `git diff` を確認し、
Conventional Commits 形式でコミットを提案する（例: `feat(claude): add <スキル名> skill`）。

## 注意

- コミット前にもう一度、公開して問題ない内容かを確認する（社内情報・シークレット・個人情報）
- 既存スキルと発火条件が重ならないよう、description の「使用タイミング」を差別化する
